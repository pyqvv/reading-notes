# CHAPTER 3 AI 기반의 신용 리스크 모델링

## 3.1 신용 리스크 관리 개요

#### 신용 리스크

대출·투자 등 금융 거래 과정에서 상대방이 채무를 상환하지 못할 가능성

#### 신용 리스크 관리

신용 리스크를 식별·평가·모니터링하는 과정

---

### 3.1.1 신용 리스크 관리의 중요성

금융 기업과 경제의 안정성을 위한 핵심 요소

---

### 3.1.2 신용 리스크 관리의 필수성

- 금융 기업의 안정적 운영 보장
- 금융 기업의 책임과 의무 준수
- 금융 시장 안정성 유지

---

### 3.1.3 신용 리스크 관리의 실천 방안

- 신용 평가 시스템 개발 및 적용
- 위험 기반 가격 정책 운영
- 지속적인 모니터링과 리스크 재평가

---

## 3.2 신용 평가 모델의 활용

#### 객관적이고 정밀한 신용 평가

- 금융 기관의 잠재적 손실 감소
- 금융 시장의 안정성 유지
- 고객 맞춤형 금융 서비스 제공 가능

#### 신용 평가 시스템 (CSS, credit score system)

- 신용도를 수치화하여 리스크를 관리하는 시스템

---

### 3.2.1 신용 평가 모델의 다양한 활용 사례

- 대출 심사
- 신용카드 발급
- 투자 리스크 산정
- 보험료 책정

---

### 3.2.2 여러 나라의 신용 평가 시스템

#### 미국

- FCRA(Fair Credit Reporting Act) 법률 기반 운영
- 신용 평가 기관 중심의 관리
- 신용 점수 모델 활용

#### 그 밖의 나라

| 나라   | 특징                                        |
| ------ | ------------------------------------------- |
| 캐나다 | 미국과 유사한 신용 평가 체계 운영           |
| 스페인 | 부정적 금융 이력을 중요 지표로 활용         |
| 독일   | 개인신용평가기관 중심으로 운영              |
| 일본   | 대형 은행 중심의 자체 신용 평가 시스템 운영 |
| 호주   | 개인신용평가기관 중심의 평가 체계 운영      |
| 중국   | 쇼핑 이력·대화 내역 등 다양한 데이터 활용   |

---

### 3.2.3 핀테크에서의 신용 평가 모델 활용

#### BNPL 서비스의 부상

- BNPL(Buy Now Pay Later): 후불결제 서비스

#### 신용 평가 모델의 역할

1. 고객의 신용도를 평가
2. 구매 가능성과 상환 능력 예측

---

#### 대안 신용 평가 모델

- 금융 거래 이력뿐만 아니라 다양한 비금융 데이터를 활용하여 신용도를 평가하는 방식
- 금융 이력이 부족한 **씬파일러**의 신용 평가 한계를 보완하기 위해 활용됨

<aside>

    씬파일러(Thin Filer)
    - 금융 거래 이력이 부족한 사람
    - 사회초년생, 주부, 노약자 등이 대표적
    - 최근 2년간 신용카드 사용 이력과 3년간 대출 이력이 없는 경우 포함

</aside>

<aside>

    카카오뱅크스코어
    - 카카오뱅크의 대안 신용평가 모델
    - 모빌리티, 도서 구매, 선물하기, 결제, 모임통장 데이터 활용
    - 금융 정보뿐 아니라 소비 패턴과 생활 습관을 분석하여 신용도를 평가

</aside>

## 3.3 신용 리스크 관리 체계

#### 신용 리스크 관리 체계의 핵심 요소

- 신용 평가 및 분석
- 대출 기준·정책 설정
- 대출 후 관리
- 데이터 분석 및 모델 활용
- 리스크 관리 시스템 구축
- 규제 준수

#### 신용 리스크 관리 체계 구성

- 데이터 체계
- 전략 체계
- AI 모델

---

### 3.3.1 데이터 체계

- 데이터 수집·저장·처리·분석 과정
- 개인신용평가기관 데이터, 대안 정보, 플랫폼 행동 정보, 그래프 데이터 등을 활용

---

### 3.3.2 전략 체계

- 금융기관이 리스크 관리와 비즈니스 목표 달성을 위해 수립하는 계획과 규칙
- 전략 수립 → 검증 → 평가 → 최적화의 순환 구조로 운영

#### 전략 체계 구성 요소

- 규칙 저장소
- 규칙 엔진

---

### 3.3.3 모델 체계

- 신용 리스크를 예측·관리하기 위한 알고리즘과 모델의 집합

| 종류           | 설명                                        |
| -------------- | ------------------------------------------- |
| 대출 전 모델링 | 대출 신청자의 신용도와 상환 능력 평가       |
| 대출 중 모델링 | 대출 기간 동안 상환 상태와 위험 모니터링    |
| 대출 후 모델링 | 상환 완료 후 신용도와 향후 대출 가능성 평가 |

---

## 3.4 AI 적용 관점에서의 신용 리스크 관리 영역 특징

- 불균형 데이터 학습 문제 존재
- 모델의 해석 가능성에 대한 요구가 높음
- 업무 목적에 따라 다양한 모델 필요
- 활용 가능한 데이터가 풍부함

---

## 3.5 신용 평가 모델 평가 지표

### 3.5.1 K-S 통계량

- 신용 평가 모델의 변별력을 평가하는 지표
- 우량 고객과 불량 고객을 얼마나 잘 구분하는지 측정

---

### 3.5.2 PSI

- 모델의 안정성을 평가하는 지표
- 시간에 따른 데이터 변화와 모델 성능 변화를 확인

---

### 3.5.3 정밀도와 재현율

- 정밀도와 재현율 사이의 균형이 중요함

#### 재현율

- 실제 불량 고객을 얼마나 잘 탐지하는지 나타내는 지표
- 불량 고객: 대출을 상환하지 못할 가능성이 높은 고객

#### 정밀도

- 불량 고객으로 예측한 대상 중 실제 불량 고객의 비율

---

### 3.5.4 AUC-ROC

- 모델의 분류 성능을 평가하는 지표
- 불균형 데이터셋 환경에서 모델 평가에 효과적임

---

## 3.6 신용 평가 모델 개발을 위한 사전 지식

<img width="370" height="66" alt="image" src="../../../images/ai-for-finance/data-analysis-time-window.png"/>

### 3.6.1 연체 기간

- 대출자가 상환 일정에 얼마나 뒤처져 지연되었는지를 나타내는 지표

---

### 3.6.2 관찰 시점

- 모델링을 위해 데이터를 수집하는 기준 시점
- 해당 시점을 기준으로 이후의 신용 행동을 예측

---

### 3.6.3 관찰 기간

- 고객의 과거 데이터를 분석하는 기간
- 이 기간의 데이터가 모델 학습에 활용됨

---

### 3.6.4 성능 기간

- 관찰 시점 이후로 평가 기간
- 고객의 상환 여부 등 신용 성과를 추척

---

### 3.6.5 종속변수

- 모델이 예측하려는 목표 변수
- 예: 고객의 대출 상환 가능 여부

---

### 3.6.6 성능 기간 설정과 빈티지 분석

#### 빈티지 분석

- 대출 실행 시점 이후 고객 행동을 시계열로 분석하는 방법
- 성능 기간을 설정하고 연체율 변화를 분석하는 데 활용됨

---

### 3.6.7 데이터 분할 전략

#### 데이터 불균형을 고려한 분할

- 불량 고객 비율이 적어 데이터 비율을 균형 있게 분할해야 함
- 불균형이 심하면 모델 성능이 저하될 수 있음

#### 외부 금융 이벤트를 고려한 분할

- 금융 위기·금리 변화 등 외부 환경 영향을 고려해야 함
- 다양한 경제 상황 데이터를 반영해 안정성을 높임

#### 시간 흐름을 고려한 분할

- 과거 데이터를 학습하고 미래 데이터를 평가에 사용
- 데이터 누수 방지가 중요함

<aside>

    데이터 누수(Data Leakage)
    - 머신러닝 및 통계 모델 학습 시, 실제 예측 시점에는 알 수 없거나 없어야 할 정보가 훈련 데이터에 포함되어 발생하는 문제

</aside>

## 3.7 머신러닝 기반 신용 평가 모델 개발

### 3.7.1 데이터 준비

- KCB, NICE 등 개인신용평가기관의 데이터 활용
- 특잇값과 결측치를 적절히 처리해야 모델의 정확도와 신뢰도를 높일 수 있음

#### 특잇값

- 데이터에서 특별한 의미를 갖는 값
- 예: NaN, -9999, 센티널값

#### 결측치 처리 방법

- 행 제거
- 평균·중앙값·최빈값 대체
- 다중 대체
- 모델 기반 대체 (알고리즘을 사용하여 결측치 예측)

---

### 3.7.2 데이터 가공(피처 엔지니어링)

#### IV와 WoE

- 변수 선택과 변환에 활용되는 지표
- IV(증거 가중치, Information Value)
- WoE(정보 가치, Weight of Evidence)

#### 이산화(구간화)

- 데이터를 구간별로 나누어 모델의 예측력과 해석력 향상
- Fine Classing: 세밀한 구간 분할
- Coarse Classing: 큰 구간으로 통합
- 장점: 노이즈·이상치 영향 감소
- 단점: 정보 손실 가능

#### 변수 선택

| 방법           | 설명                           |
| -------------- | ------------------------------ |
| 필터 방법      | 변수와 목표 변수의 관련성 평가 |
| 래퍼 방법      | 모델 성능을 기준으로 변수 선택 |
| 모델 기반 방법 | 모델이 제공하는 중요도를 활용  |

---

### 3.7.3 모델링

#### 주요 모델

| 모델           | 특징                                    |
| -------------- | --------------------------------------- |
| 로지스틱 회귀  | 해석력이 높으나 복잡한 관계 학습에 한계 |
| 트리 기반 모델 | 비선형 관계 학습에 강함                 |
| 딥러닝 모델    | 높은 성능을 보이나 해석이 어려움        |

#### 모델 선택 기준

- 해석력
- 성능
- 비용
- 규제 준수

---

### 3.7.4 스코어링

- 모델 결과를 신용 점수로 변환하는 과정
- Base Score, PDO 등을 활용
  - Base Score: 기준이 되는 신용 점수
  - PDO (Points to Double the Odds): 연체 가능성이 2배 변할 때 점수가 얼마나 변하는지를 나타내는 값

---

### 3.7.5 모델의 해석력

- 로컬 해석력: 개별 예측 결과 설명
- 글로벌 해석력: 모델 전체 동작 설명

---

### 3.7.6 모델 배포

- 웹 서비스
- 클라우드
- 온프레미스 서버
- 엣지 디바이스
- 머신러닝 모델 서버

---

### 3.7.7 모니터링

- 모델 성능과 데이터 변화 지속 관찰
- 데이터 분포 변화(Data Drift)에 대응
- 모델의 예측력 유지 및 개선 지원
